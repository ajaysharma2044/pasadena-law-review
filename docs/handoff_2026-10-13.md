## Security review (S8)

An independent review of the whole codebase found seven issues. All are fixed, each with a regression test (details in `docs/verification.md`).
- The most serious: admin and editor pages relied on their layout for access control. A crafted client-navigation request could read admin data (for example, the member list) without signing in.
- Every page now checks access itself.
- The services also check roles.

## Decisions worth knowing

- **Netlify + Neon + Resend.** Netlify was the owner's choice. Neon, because Netlify's own database product requires a credit-based plan. Netlify Blobs, for private attachments.
- **PGlite locally and in tests:** real Postgres behaviour without Docker. The same SQL migrations run everywhere.
- **Markdown editor with a toolbar and preview,** not WYSIWYG. Footnotes and small caps are first-class, and the output is sanitized the same way at preview and at publication.
- **Confirmation links don't sign you in.** That closes a login-CSRF trick; users sign in once after confirming.
- **Published articles are fixed copies** (database-enforced). Editing after publication never changes what readers see until an administrator publishes again.
